Routes

Add a routeServe any container at https://<name>.

Set VIRTUAL_HOST on the container, and VIRTUAL_PORT if the app doesn't listen on port 80 and its image exposes more than one port. The route shows up here a second after the container starts.

Docker Compose

services:
  app:
    image: my-app
    environment:
      VIRTUAL_HOST: myapp   # https://myapp.
      VIRTUAL_PORT: 3000    # the port the app listens on

docker run

docker run -d --name myapp -e VIRTUAL_HOST=myapp -e VIRTUAL_PORT=3000 my-app

Dockhand

Open the stack in Dockhand, add VIRTUAL_HOST (and VIRTUAL_PORT) to the service's environment, then redeploy.

Good to know

  • No ports or networks needed: local-env connects the container to the proxy for you.
  • A short name gets the domain: myapp becomes myapp.. A full hostname is used as is.
  • Several hosts: separate them with commas, as in VIRTUAL_HOST: myapp,api.
  • The app must listen on 0.0.0.0, not localhost, so the proxy can reach it.
  • Containers with a route can call each other's URLs, such as https://api.. To trust the certificate, mount the local CA and point SSL_CERT_FILE (or NODE_EXTRA_CA_CERTS) at it: "${HOST_HOME}/Library/Application Support/mkcert/rootCA.pem:/etc/local-env/ca.pem:ro".
